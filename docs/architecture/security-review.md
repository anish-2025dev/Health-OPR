# Security review (pilot release, November 2026)

A review of the whole application before the pilot. It covers the controls that are in place, how each
one is verified, and what remains open.

## Controls in place

| Area                 | Control                                                                                                                                                                                                                                                                                                     | Verified by                                                                                                           |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Tenant isolation     | `organization_id` on every tenant table. RLS enabled **and forced**. Each request runs in `withTenant()` and also filters by organization in code. `withSystem()` is limited to pre-tenant lookups (sign-in, organization by code, tracking code, WhatsApp number to hospital) and the WhatsApp retry sweep | Cross-tenant integration tests in every module (`apps/api/tests/integration`); review of every `withSystem` call site |
| Database role        | API refuses to start in production as a superuser or `BYPASSRLS` role; TLS required to the database                                                                                                                                                                                                         | `server.js` startup check; config tests                                                                               |
| Staff auth           | 15-minute access tokens; rotating refresh cookie (HttpOnly, SameSite=Strict, scoped path) with reuse detection; lockout after 5 failures; rate limits; forced first-login password change                                                                                                                   | `auth.test.js`                                                                                                        |
| Employee auth        | Mobile + OTP (HMAC-hashed, 5 minutes, 5 attempts, cooldown, per-window cap). An OTP never opens a staff account                                                                                                                                                                                             | `auth.test.js`, `attendance.test.js`                                                                                  |
| Patient auth         | Separate account, token audience and key; staff and patient tokens are rejected by each other's APIs; per-hospital membership required; refresh reuse revokes all sessions                                                                                                                                  | `patients.test.js`                                                                                                    |
| Authorization        | Permission checked on the backend for every route; object ownership checked (own queue for doctors, own team for managers, authorized family links only for patients)                                                                                                                                       | `permissions.test.js` and module tests                                                                                |
| Attendance integrity | Geofence (distance and GPS accuracy) **and** SMS OTP both required                                                                                                                                                                                                                                          | `attendance.test.js`                                                                                                  |
| Payroll integrity    | Approved runs and approved statutory rules immutable (database triggers); attendance and leave locked for approved periods; reproducible calculations                                                                                                                                                       | `payroll.test.js`, `statutory.test.js`                                                                                |
| Concurrency          | Bookings lock the doctor row; tokens from a transactional counter; unique indexes against double booking; idempotency keys on booking, walk-ins and WhatsApp                                                                                                                                                | `clinic.test.js` (parallel bookings)                                                                                  |
| Webhooks             | Meta signature (HMAC-SHA256, timing-safe) checked over the raw body; dedupe by message ID; quick acknowledgement                                                                                                                                                                                            | `whatsapp.test.js`, `whatsapp-adapter.test.js`                                                                        |
| Privacy              | Phone ≠ patient identity; no automatic merges; WhatsApp never creates patients; consent per purpose with history; notifications without medical details; tracking page shows no names; message text cleared after WhatsApp processing                                                                       | `patients.test.js`, `whatsapp.test.js`, `clinic.test.js`                                                              |
| Logging              | Request bodies not logged; redaction of auth headers, cookies, OTPs, codes, tokens, bank and identity fields                                                                                                                                                                                                | `logger.js` `REDACT_PATHS`                                                                                            |
| Browser              | Helmet on the API; static sites send CSP (`script-src 'self'`), `X-Frame-Options: DENY`, `nosniff`, Referrer-Policy (`no-referrer` on the patient site so tracking links don't leak) and Permissions-Policy (geolocation only on the staff site)                                                            | `render.yaml`; both builds checked under the CSP with no violations                                                   |
| Secrets              | None in the repository; `.env.example` placeholders only; gitleaks in CI; generated `APP_SECRET_KEY`                                                                                                                                                                                                        | CI secret scan                                                                                                        |
| Dependencies         | `npm audit --omit=dev`: 0 known vulnerabilities at release                                                                                                                                                                                                                                                  | CI and manual check                                                                                                   |

## Open items / accepted risks for the pilot

| Item                                                      | Risk                                                                             | Plan                                                                  |
| --------------------------------------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Hosting region is Singapore                               | Data stored outside India                                                        | Legal review before real data; Indian region if required              |
| Live screens poll every 5–15 s                            | Load grows with many open screens                                                | Fine for a pilot; switch to WebSocket push if needed                  |
| Patients visible to all branches of a hospital            | Wider staff access than strictly needed                                          | Confirm with each hospital; branch scoping can be added               |
| Patient account tables are platform-level (no tenant RLS) | They hold only phone numbers and sessions, but bugs there are not stopped by RLS | Queries always keyed by account ID; tests cover cross-hospital access |
| No automated penetration test                             | Unknown issues                                                                   | External pen test before onboarding hospitals beyond the pilot        |
| TDS is a monthly amount entered by payroll                | Manual errors                                                                    | Payroll adviser review each month                                     |
| Error tracking is log-based                               | Errors may go unnoticed                                                          | Add an error-tracking service (with PII scrubbing)                    |
